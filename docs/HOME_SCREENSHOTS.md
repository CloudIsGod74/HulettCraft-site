# Front-page archive screenshots

The home page now shows two equal 16:9 frames instead of three images at their natural dimensions. Images fit inside the frame without cropping; narrow or unusually shaped screenshots have a dark surround. Only the screenshots are shown: there are no visible collection titles, captions or credit panels. Descriptive alt text remains, and each image links directly to its full screenshot. Cards stack on small screens. The top banner and the rest of the website keep their existing behavior.

The browser loads a random pair when this section comes into view, then changes the pair every 12 seconds. **Previous screenshots** and **Next screenshots** arrows browse up to 20 recently displayed pairs; going forward past the latest pair loads a new random selection. History lasts only for the current page visit, and images are decoded again before displaying a revisited pair. **Shuffle screenshots** starts a new random forward path. All manual controls work while paused. Playback messages are screen-reader-only; no visible status line or extra text row is shown beneath the photos. The icon-only **Pause/Play slideshow** control has an accessible label and tooltip. Its pause preference is remembered for the browser session. Reduced-motion visitors start paused and can choose Play. Automatic queries stop when the section is off-screen or the tab is hidden. A focused screenshot link or an open screenshot viewer also prevents an automatic swap. Only the current pair and its replacements are downloaded, rather than preloading the archive.

`/api/gallery/spotlight.json` chooses from all approved, publicly serveable raster screenshots under the existing HulettCraft, Hytale and Modded season prefixes, including unassigned seasons, plus the existing public local archive images listed in `src/config/spotlight.ts`. It follows all R2 listing pages. Pending uploads, unsupported MIME types, unrelated files and invalid keys never enter the pool. Newly approved R2 images become eligible after the five-minute listing cache refresh; no website rebuild is needed. Adding a new local asset still requires updating the configuration and building normally.

Selections contain two distinct URLs, with at most one Hytale screenshot, and prefer images outside the previous pair. The Hytale limit takes priority over exclusions: a previously shown Minecraft image can be reused to keep a valid pair. A hypothetical Hytale-only archive produces just one image rather than two Hytale images. Selection is random among eligible images, so larger seasons have proportionally more representation; repeated scenes may still exist as separate archive files. Descriptions use the existing approved metadata for image alt text; visible captions and credits remain available in the galleries. Clicking or tapping a screenshot opens that exact image in a larger modal viewer on the homepage. The viewer supports its Close button, Escape, and backdrop dismissal; closing returns focus to the selected screenshot and retains the slideshow pause preference. The separate Explore the archive link still opens the gallery. Without JavaScript, screenshot links open the image directly. The API's exclusion parameters only filter known entries; they do not cause any supplied URL to be fetched.

Each isolate caches its archive listing for five minutes, with an optional Cloudflare Cache API snapshot to share it at the edge. Random pair responses are `no-store` so visitors don't get stuck with a CDN-cached pair. Snapshot refreshes are driven by requests. During a listing outage, a previously loaded archive can remain usable for up to 24 hours; otherwise the local archive is used. Failed listing requests retry no more than once a minute per warm service instance. The image route still enforces its public key and raster type boundaries when an image is fetched. An old cached listing may temporarily reference a deleted image; the browser decodes both replacements before changing either frame and retains the current pair if either fails.

Two local screenshots remain visible without JavaScript or if the selection service cannot be reached. No R2 writes, renaming, metadata edits, KV writes, new bindings, secrets or dependencies are introduced. Tests use memory-only storage and the generated local Wrangler state; they do not contact production R2.
